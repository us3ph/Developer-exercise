# Implementation choices

- Python 3.11+, FastAPI, standard-library SQLite, and pytest. No team stack was provided.
- Fixture-only defaults: every seeded dossier starts at `submitted`; D-2041 uses CIH Bank, and D-2077 uses `Banque fictive`. The brief specifies CIH for D-1234 and adviser Bennani, but does not specify Sara's second bank or initial statuses.
- IDs, dates, people, attachments, and messages are simulated. No messaging provider is contacted.
- WhatsApp fixtures use the simplified inbound `messages[]` object requested in the exercise. Meta documents `from`, `id`, `timestamp`, `type`, `text.body`, and inbound reply `context.id` in its [messages reference](https://www.postman.com/meta/whatsapp-business-platform/folder/1dtuocp/messages-object) and [Cloud API webhook examples](https://www.postman.com/meta/whatsapp-business-platform/documentation/wlk6lh4/whatsapp-cloud-api?entity=request-13382743-ba924e99-3d98-4954-b4e3-73a519939c33). Reviewed on 2026-10-02. `timestamp` is event time in Unix seconds; inbound `context.id` differs from outbound send `context.message_id`. Full webhook envelopes and status events are outside the required simplified adapter.
- The user's instruction overrides the plans' commit requirement: do not commit or push.
- Complete one step at a time, mark it finished, report the result, and stop. Start the next step only after the user's explicit confirmation.
- Step 2 uses Pydantic to validate the simplified payloads and dataclasses for normalized messages, lookup facts, and routing decisions. The pure router has no database access, logging, network calls, or AI analysis.
- WhatsApp references are complete, case-sensitive `D-xxxx` identifiers. One unique reference belonging to the sender wins, even alongside an unrelated reference. If no explicit reference belongs to the sender, triage wins before the phone fallback (case E). Multiple owned references continue to the active-dossier rules. Explicit references and outgoing context may attach inactive dossiers; phone fallback and dossier choices use only active dossiers.
- Mailboxes and header names are normalized to lowercase, including recipients in `to` and optional `cc`. Message-ID values retain their case and opaque contents. Email rules collect unique existing dossiers; ambiguity continues to the next rule. `In-Reply-To` and all IDs in `References` are considered together, and must identify outgoing emails. Email routing does not require the sender to be a participant.
- Dates are stored in UTC. WhatsApp uses the supplied event timestamp; email uses its optional event timestamp or receipt time. ISO dates and injected receipt times without a timezone are interpreted as UTC.
- The simplified adapter supports WhatsApp `text`, `document`, and `image` payloads; other types are rejected. Attachment metadata and original message text are retained. No attachment downloads or email text cleanup are performed.
- `log_dossier_choice` is the logging helper outside the router. It logs the simulated interactive list for `needs_choice`, including Sara's two dossier references. Step 3 will call it after saving a new message so duplicate deliveries do not repeat the log. No HTTP endpoints or incoming-message persistence have been added in Step 2.
